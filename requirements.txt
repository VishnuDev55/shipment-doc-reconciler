# RUNTIME dependencies -- pinned. This is what the Dockerfile installs, so
# nothing in here is test-only or lint-only. That is the fix for docs/AUDIT.md
# finding R8 ("Test-only deps (pytest, httpx) sit in the runtime file, so the
# production image installs the test suite's dependencies").
#
# WHICH FILE IS WHICH, and why three exist
#   requirements.txt        this file. Direct runtime deps, exact pins. Use it
#                           for the production image and for `make setup`.
#   requirements-dev.txt    this file plus the lint/type/test tools. Use it for
#                           development and CI (`-r requirements.txt` at its top).
#   requirements.lock.txt   full `pip freeze` of the validated environment:
#                           every transitive package too, at the exact version
#                           the passing suite actually ran against. The two
#                           ranged files above cannot answer "what did we test";
#                           this one can. It is a reproducibility record, not
#                           something the Dockerfile installs (it also contains
#                           the dev tools, which the image must not get).
#
# Pins were taken from `python -m pip list --format=freeze` in the project venv
# (Python 3.11.15, the same minor as `FROM python:3.11-slim`), recorded 2026-10-04.
# Every line below is a DIRECT import, verified by AST-scanning all 70 .py files
# in app/, scripts/, tests/ and fixtures/ -- no transitive package is listed.
#
# Two corrections against the previous version of this file:
#   * httpx was classed as a test dependency in docs/AUDIT.md R8. It is not:
#     app/discovery.py:244 constructs httpx.AsyncClient to probe provider model
#     catalogs. Removing it from the runtime file would break model discovery in
#     the container.
#   * xhtml2pdf was commented here as "Fixture generation only". It is not:
#     app/pdf.py:274 imports it and app/main.py:36 wires render_pdf into the PDF
#     export endpoint. It is a runtime dependency.
#
# `pip check` on the resulting environment reports no broken requirements.
# =============================================================================
