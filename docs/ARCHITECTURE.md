# Architecture

What the system is, where the boundaries are, and which rules may not be broken.
This is the document to read before changing anything; the module docstrings carry
the detail, and this carries the shape.

---

## The one decision everything else follows from

A vision model transcribes. Deterministic Python decides.

```
bytes ──ingest──▶ page JPEGs ──model──▶ verbatim strings ──▶ normalizers ──▶ compare_key
                     │                                                    │
                     └──────────── evidence images ───────────────────────┴──▶ report
```

The model's entire output surface is a JSON object of strings and booleans
(`app/models.py:ExtractedField`). It never receives a number to add, a unit to
convert, or a judgement to make, and it is never asked which document disagrees.
Every comparison in the report is a pure function of normalized values, so a
verdict can be reproduced, unit-tested, and argued with — and a model that
hallucinates a plausible total cannot produce a plausible *verdict*.

Seven invariants enforce this. They are not style preferences; each one is a
failure mode that was observed or reasoned out, and each is pinned by a test.

| # | Invariant | Where it is enforced |
|---|---|---|
| 1 | The model never does arithmetic | `app/models.py` types every value as `str \| None`; normalizers own parsing |
| 2 | `canonical` (for humans) and `compare_key` (for the engine) stay separate | `NormalizedField`; `app/compare/__init__.py` compares keys only |
| 3 | Never convert currencies; never guess an absent field | `app/normalize/money.py` returns a hard conflict across currencies; `present=false` is preserved end to end |
| 4 | Text inside documents is data, never instructions | prompt rule 5 (`app/prompt.py`); values reach the UI through `textContent` only |
| 5 | The test suite makes zero network calls | `tests/conftest.py` patches the socket layer for the session |
| 6 | Be honest about live vs cached vs authored | `source` on every document, `result_source`/`live_calls` on every run, restated in the PDF and the UI |
| 7 | Never leak API keys | keys are compared, not stored; masked in `/api/config`; absent from reports, ZIPs, PDFs and error bodies |

## Module map

**Contract**
- `fields.py` — the ten fields, five document types, per-type expectations and surface hints. The single source: schema, prompt, normalizer dispatch, comparator table, UI rows and fixtures all derive from it. Adding a field means editing this file.
- `models.py` — Pydantic v2 models: the extraction contract, the normalized/comparison types, and the persisted report.
- `config.py` — settings plus the three version tags (`PROMPT_VERSION`, `NORMALIZER_VERSION`, `COMPARATOR_VERSION`, and `LINEITEMS_PROMPT_VERSION` for the second contract).

**Getting pixels into the model**
- `ingest.py` — bytes → canonical JPEGs. Magic-byte sniffing, an explicit pixel ceiling, EXIF orientation, one long-edge size. Everything downstream, including the cache key, works on these images rather than on the upload.
- `prompt.py` — the system contract, the user turn, the page markers, and the two fallback rungs.
- `client.py` — transport, backoff, the capability probe, the five-rung extraction ladder, and the line-item read. `providers.py` resolves endpoints.
- `discovery.py` — asks each host what it actually serves before trusting a configured model name.

**Getting truth out of strings**
- `parse.py` — rungs 1–3 (load, repair, coerce). One unreadable field never fails a document.
- `normalize/` — one module per kind: `number`, `money`, `weight`, `quantity`, `container` (ISO 6346), `hs_code`, `party`, `categorical`.
- `compare/__init__.py` — the tolerance table and per-kind comparators. Frozen constants, no model.
- `textlayer.py` — the PDF's own embedded text, recovered at ingest without a model and without OCR. This is what the evidence check has to work against.
- `verify.py` — is the line the model quoted actually on that page? Four states, and a value that fails is withdrawn from the comparison rather than trusted.
- `rules.py` — cross-field sanity that no single-field comparison can see (net above gross, weight-basis confusion).
- `mathcheck.py` — arithmetic inside one document, so a shipment whose four papers all repeat the same wrong total stops being a pass.
- `scoring.py` — a 0–100 risk score where every point traces to a named rule.
- `severity.py` — one table that gives every finding one level, and the banner that reads them. Stricter than the verdict is allowed; kinder is not.
- `correction_email.py` — the drafts that follow from those findings: addressed to roles rather than people, generated by rule with no model in the loop, and never stating an expected value the paperwork did not print.
- `lineitems.py` — opt-in goods-line matching. Exact, never fuzzy.

**Optional model calls, all additive**
- `summary.py` / `narrative_cache.py` — an executive summary. `adjudicate.py` — a second opinion on genuinely ambiguous comparisons. Neither can change a status, and both are marked superseded when a human corrects a value underneath them.
- The AI briefing (`ENABLE_BRIEFING`, `build_briefing_prompt` in `adjudicate.py`) is **deprecated**: `correction_email.py` drafts the same supplier letter by rule with no model in the loop. The code path and the config option remain, but the default is off and it is no longer part of the recommended flow.
- `consensus.py` — a second provider reads the same pages; disagreement is a review marker, not a verdict.

**Around the edges**
- `orchestrator.py` — the run: fan-out, report assembly, SSE publishing, corrections, bounded memory.
- `store.py` — filesystem as the database. `export.py` / `pdf.py` — the artifacts.
- `main.py` — FastAPI: routes, auth, session cookie, security headers, rate limit.
- `limits.py` — a sliding window on the one endpoint that spends money.
- `web/` — one HTML file, one stylesheet, one script. No framework, no build step, no CDN.

## Why the frontend is still one file

`web/app.js` is ~1,600 lines with nine commented section dividers. Splitting it
into ES modules was measured, not assumed to be a good idea: slicing at the
section boundaries and computing the cross-chunk reference graph produced modules
that are mutually cyclic — `report ↔ run` (rendering calls `poll`, the run loop
calls `renderReport`), `run ↔ intake`, `net ↔ config` (the transport needs
`configHeaders`, the drawer needs `getJSON`), and a longer loop through
`rail → net → config → rail`. A cycle-tolerant module system would still load it,
but the dependency story would be strictly worse than "one file, one scope", and
the refactor would touch a UI currently verified by 12 browser tests.

`core` — the constants, `state`, `$` and `el` — is the one genuinely clean leaf,
and is the only piece worth extracting on its own. (Getting that answer required
fixing the analysis: a first pass reported a `core → report` edge that turned out
to be the `showRaw: false` property on `state` matching the `showRaw()` function
name. Word-boundary matching over source text is not a dependency graph.)

A genuine modularisation needs an action/event seam between rendering and
run-control first — a redesign, not a split. It is deliberately not done here.
If you pick it up, start by breaking `report → poll` and `net → config`, not by
moving code.

## Concurrency and state

One process-global `Reconciler` (`app/main.py:configure/reconciler`) holds the
clients, the in-memory report cache (an `OrderedDict` bounded by
`MAX_REPORTS_IN_MEMORY`), and the running tasks. A shipment's documents are read
with `asyncio.gather` behind a semaphore (`MAX_CONCURRENCY`).

Two things that look like bugs and are not:
- The shared client cannot carry a per-run raw-output directory, so `raw_dir` is a
  *parameter* on every call. A constructor argument would send two concurrent
  runs' evidence to whichever directory was created first.
- The capability probe is guarded by an `asyncio.Lock` created in `__init__`. A
  lazily-created lock looked initialised because `getattr(self, "__probe_lock")`
  never sees the name-mangled attribute — the concurrency test caught it.

CPU-bound work (PDF rasterisation, image decoding, disk writes) runs through
`run_in_threadpool`; on the event loop it would stall every other shipment.

## Failure policy

A document that fails is marked failed, still rendered, and retryable on its own.
It never aborts the shipment and never cancels its siblings. A 2-of-3 result is
useful; a 500 is not. The same rule applies downward: a cache write failure does
not lose a successful extraction, and a narrative failure does not change a
verdict.

A per-document cross-provider fallback (`VISION_FALLBACK`, default on) reads a
document on the other host when the configured one returns nothing usable —
never a partial answer, and never in DEMO_MODE. The surviving answer is stamped
on the document's own provider/model, so the report still names who really read
it.

## Storage

`runs/{shipment_id}/` holds `report.json`, the page images, `raw/` model bodies
and the export artifacts. There is no database, deliberately: a run is a document
about documents, and a directory a person can `ls` survives the app.

## Known seams

Two globals are deliberate and worth naming rather than hiding. `get_settings()`
in `app/config.py` is `@lru_cache`d so a process reads its environment once, and
`app/main.py` keeps `_reconciler` behind `reconciler()` / `configure()`. The
injection point is what lets every test configure a reconciler without touching
the environment; replacing the cache with a per-request read and threading the
reconciler through FastAPI state is a design change, not a rename, and 18 tests
in `tests/test_config.py` depend on the current shape. Until that seam is built:
one process, one settings object, one reconciler, and `configure()` is the only
supported way to replace it.

**Two details the diagram cannot show.** `fields` is an object keyed by the ten
fixed names (`app/fields.py:FIELD_ORDER`), not an array — so structural
completeness does not depend on the model remembering to include everything. And
the `canonical` / `compare_key` split exists to stop a specific classic bug: a
display string like `"12,450 kg"` being string-compared against
`"12450.0 kg"`. The engine touches only `compare_key`, the UI only `canonical`
and `raw_value`, and they are produced together rather than derived from each
other. The seven invariants above are the full contract; this diagram is just
where they sit.

## How extraction works

**One model call per document**, all of that document's pages in the same call
as separate image parts, each preceded by a `--- PAGE n ---` marker so the
reported `page_index` means something.

The system prompt states the contract without softening it. The rule that
matters most:

> If a field is not visibly printed, set `present=false`, `value=null`. NEVER
> infer, calculate, or guess. An absent field reported as absent is correct. An
> absent field filled in with a plausible guess is a failure.

A guessed value looks plausible, passes every downstream check, and quietly
destroys the premise of the whole tool. The prompt also instructs the model to
treat text found inside documents as **data, never instructions** — a scanned
page can carry adversarial wording.

---


### Structured output: probe, and trust the endpoint over the docs

Token Factory documents `response_format: json_schema`, gated **per model** by a
"JSON mode" tag on the model card — so availability cannot be assumed from the
host. Both hosts also reject the bare-schema shape their own docs show and accept
OpenAI's `{name, strict, schema}` envelope; that measurement, and the
unsupported-vs-busy distinction the probe has to make, belong to
[`docs/PROVIDERS.md`](PROVIDERS.md) §Structured output.

What is architecture: one tiny text-only probe runs at startup per endpoint and
caches its verdict — `strict` → `json_object` → `plain` — and it is never re-run
per request. The chosen mode is recorded on the report as `run.json_schema_mode`,
and `test_client.py` pins the envelope shape so a future "correction" back to the
documented form fails a test. On the development account the probe returns
**strict** for omni and downgrades to `json_object` for MiniCPM-V.

---


### The retry ladder, cheapest first

| Rung | Cost | What happens |
|---|---|---|
| 1 | free | `json.loads()` directly |
| 2 | free | repair text: strip markdown fences, extract the first **balanced** `{...}` span (string- and escape-aware), drop trailing commas, fix smart quotes |
| 3 | free | coerce into Pydantic: missing keys → `present=false`, non-string value → `str()`, out-of-range confidence → clamped, unknown `doc_type` → `"other"` |
| 4 | 1 call | feed the bad output **and the parser error** back, ask for corrected JSON |
| 5 | 1 call | retry with a simplified schema |
| 6 | — | give up cleanly: document marked `failed`, shown with a retry button |

One bad field never fails a whole document, and one failed document never aborts
a shipment. A 2-of-3 result is useful; a 500 error is not.

Transport failures (timeout / 429 / 5xx) are handled **below** the ladder with
exponential backoff — 3 attempts at 1s / 4s / 12s plus jitter — so a network
blip never burns a ladder rung. Every raw response is written to `runs/…/raw/`,
including failed attempts.

## Design decisions worth stating out loud

**No OCR fallback.** Layering Tesseract or PaddleOCR under the VLM would mean
adjudicating between two extractions that disagree — a multi-day rabbit hole for
no demo gain. The signal OCR would provide ("this value is suspect") is already
produced three ways: the ISO 6346 checksum catches misreads with certainty, the
model's self-reported confidence flags illegibility, and normalizer warnings
flag ambiguity. Each is cheaper and more honest than a second engine.

**No bounding boxes from the model.** VLM box coordinates are unreliable, and a
rectangle the model *guessed* would dress up a guess as precision. The highlight
in the evidence viewer is therefore measured, not asked for: it comes from the
PDF's own text layer, and only for a quote that appears verbatim inside one
printed line. Where the page has no text layer, the evidence stays what it always
was -- a verbatim line, a page number and the viewable page -- and the viewer says
there are no coordinates rather than drawing a shape anyway.

**Filesystem over a database.** There are no queries, no relations and no
multi-user access. `runs/{shipment_id}/` *is* the artifact — the ZIP export is
literally that directory compressed.

**Polling over WebSockets.** One JSON file per shipment, polled every second.

**No auth.** Shipment IDs are `secrets.token_urlsafe(12)`. Unguessable is
sufficient access control for a public demo.

**Ten scalar fields, plus goods lines behind a flag.** The contract grew from six
fields to ten; per-line matching shipped after that, off by default
(`ENABLE_LINE_ITEMS`), because it costs one more vision call per document and
deliberately cannot move a verdict. Why its matching is exact-only, with no
similarity band, is in [`docs/FEATURES.md`](FEATURES.md) §Line by line.

The four-tier cache is deliberate. Each fixture document has a **NVIDIA omni**
live response, two **Nebius** live responses (`MiniCPM-V-4_5` and
`Nemotron-3.5-Super-VL`), and a **hand-authored** fallback. Any
`VISION_PROVIDER` and `NEBIUS_VISION_MODEL` setting therefore finds a real answer
offline, and provenance is labelled honestly in the report — replaying an
authored fixture is never reported as a model result.
